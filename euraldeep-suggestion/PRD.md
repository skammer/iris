# Определение источника запросов по User-Agent в NeuralDeep

## Зачем

В таблице запросов neuraldeep.ru колонка «Откуда» пустая на предоставленном скриншоте. Пользователю нужно видеть, какое приложение или клиентская библиотека отправили запрос, чтобы различать интеграции одного ключа API и разбирать ошибки и расходы.

Скриншот подтверждает симптом, но не причину: заголовок может отсутствовать у клиента, теряться на прокси, не сохраняться или не отображаться. Цель — провести User-Agent от входящего запроса до таблицы.

## Что сделать

- Определять источник для **всех входящих запросов публичных API NeuralDeep**, независимо от адреса, метода HTTP, формата тела и способа передачи ответа. Новые методы должны получать эту поддержку автоматически.
- Сохранять исходный `User-Agent` и отдельно определённые название и версию клиента.
- Показывать в «Откуда» название и версию. При наведении на ячейку показывать исходную строку `User-Agent` без нормализации; также оставлять её в подробностях запроса для устройств без наведения.
- Отсутствующий заголовок отображать как «Не указан». Непонятный формат — как «Не распознан», с доступной исходной строкой.
- Документировать рекомендуемый клиентский заголовок: `User-Agent: iris/0.1`, где версия соответствует сборке приложения.

## Охват API

В [официальной справке NeuralDeep](https://neuraldeep.ru/llms-full.txt) описаны `/v1/chat/completions` и `/v1/responses`. Отдельный устаревший `/v1/completions` в проверенной справке не найден.

Требование распространяется также на векторные представления (`/v1/embeddings`), ранжирование (`/v1/rerank`), аудио (`/v1/audio/*`), поиск (`/v1/search/*`), распознавание документов (`/v1/ocr/*`), изображения (`/v1/images/*`), обезличивание (`/v1/pii/*`), классификацию (`/v1/decisions`), чтение лимитов (`/v1/limits`), получение состояния задач и результатов. Этот перечень — примеры из справки, а не ограничение.

Включить отдельные публичные API платформы, в частности SpeechCore и Drift. Заголовок собирать для каждого внешнего HTTP-запроса; в фоновой задаче сохранять источник запроса, создавшего её. Внутренние обращения между сервисами не должны подменять исходный источник.

## Как реализовать

1. Проследить один запрос с заданным User-Agent: входной прокси → API → запись истории → API кабинета → таблица. Исправить место потери; проверить все публичные точки входа платформы.
2. Подключить сбор заголовка в общем входном обработчике каждого API до проверки авторизации и выбора метода, без списка разрешённых адресов. Читать имя заголовка без учёта регистра. Сохранять источник в журнале каждого запроса, включая ошибки, неизвестные адреса и ограничения частоты. Переносить эти данные в историю и API кабинета там, где создаются записи запросов.
3. Добавить в запись поля исходной строки, названия и версии клиента, допускающие отсутствие значения. Для хранения ограничить строку до 1024 символов; при обрезке показывать соответствующую пометку. Подсказка при наведении и подробности должны выводить сохранённую строку как текст с экранированием.
4. Разбирать стандартные обозначения вида «название/версия», комментарии и несколько обозначений через пробел. Приложение определяется первым обозначением; если присутствует только клиентская библиотека, показывать её. Не пытаться угадать приложение по библиотеке.
5. Учесть форматы официальных библиотек, где версия стоит отдельно: `OpenAI/Python 2.8.1` → `OpenAI Python`, версия `2.8.1`. Не считать `Python` версией. Аналогично обработать Anthropic; для Google распознавать `google-genai-sdk`.
6. Ошибка разбора не должна ломать обработку запроса или запись истории. User-Agent — заявленная клиентом информация, не подтверждённая идентичность.
7. Старые записи заполнять только при наличии сохранённого User-Agent. Иначе оставлять «Не указан».

## Критерии приёмки

| Входной заголовок | Колонка «Откуда» |
| --- | --- |
| `User-Agent: iris/0.1` | `iris 0.1` |
| `user-agent: iris/0.1 clj-http/3.13.1` | `iris 0.1` |
| `User-Agent: OpenAI/Python 2.8.1` | `OpenAI Python 2.8.1` |
| `User-Agent: custom-client/1.2 (integration)` | `custom-client 1.2` |
| Заголовок отсутствует или пустой | `Не указан` |
| `User-Agent: ???` | `Не распознан` |

Проверить общий обработчик и передачу источника для всех публичных точек входа. Обязательные сценарии: чат и Responses с потоковой передачей и без неё; векторные представления; загрузка аудио или документа; создание фоновой задачи; чтение состояния, результата и лимитов; ошибки 401, 404, 429 и 500. Новый маршрут без собственного кода обработки User-Agent тоже получает источник.

В таблице после обновления страницы название сохраняется. При наведении на «Откуда» отображается исходная строка, например `iris/0.1 clj-http/3.13.1`, а не только `iris 0.1`; это работает и для «Не распознан». При отсутствии заголовка подсказка сообщает «User-Agent не передан». Исходная строка доступна также при фокусе с клавиатуры и в подробностях. Неизвестный, длинный или содержащий разметку заголовок не ломает запрос и интерфейс.

## Основания и ограничения

Формат обозначений описан в [стандарте HTTP](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.1.5). Особые форматы проверены по исходникам официальных клиентских библиотек [OpenAI](https://github.com/openai/openai-python/blob/main/src/openai/_base_client.py), [Anthropic](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/_base_client.py) и [Google](https://github.com/googleapis/python-genai/blob/main/google/genai/_api_client.py).

Это предложение для команды NeuralDeep. Охват API сверён с опубликованной справкой 4 октября 2026 года. Серверный код, фактическая доступность методов и реальные входящие заголовки не проверены; конкретное место потери предстоит установить. Изменения клиентского кода Iris в эти требования не входят.
