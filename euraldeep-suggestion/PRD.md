# Определение источника запросов по User-Agent в NeuralDeep

## Зачем

В таблице запросов neuraldeep.ru колонка «Откуда» пустая на предоставленном скриншоте. Пользователю нужно видеть, какое приложение или клиентская библиотека отправили запрос, чтобы различать интеграции одного ключа API и разбирать ошибки и расходы.

Скриншот подтверждает симптом, но не причину: заголовок может отсутствовать у клиента, теряться на прокси, не сохраняться или не отображаться. Цель — провести User-Agent от входящего запроса до таблицы.

## Что сделать

- Поддержать `/chat/completions` и `/responses`, включая потоковую передачу ответа, успешные и ошибочные запросы, попадающие в историю.
- Сохранять исходный `User-Agent` и отдельно определённые название и версию клиента.
- Показывать в «Откуда» название и версию; исходную строку — в подробностях запроса.
- Отсутствующий заголовок отображать как «Не указан». Непонятный формат — как «Не распознан», с доступной исходной строкой.
- Документировать рекомендуемый клиентский заголовок: `User-Agent: iris/0.1`, где версия соответствует сборке приложения.

## Как реализовать

1. Проследить один запрос с заданным User-Agent: входной прокси → API → запись истории → API кабинета → таблица. Исправить место потери; прокси должен сохранять заголовок исходного клиента.
2. В общем обработчике запросов читать заголовок без учёта регистра имени. Добавить в запись истории поля исходной строки, названия и версии клиента, допускающие отсутствие значения; передавать их в API кабинета. Для хранения ограничить строку до 1024 символов, отображать как текст с экранированием.
3. Разбирать стандартные обозначения вида «название/версия», комментарии и несколько обозначений через пробел. Приложение определяется первым обозначением; если присутствует только клиентская библиотека, показывать её. Не пытаться угадать приложение по библиотеке.
4. Учесть форматы официальных библиотек, где версия стоит отдельно: `OpenAI/Python 2.8.1` → `OpenAI Python`, версия `2.8.1`. Не считать `Python` версией. Аналогично обработать Anthropic; для Google распознавать `google-genai-sdk`.
5. Ошибка разбора не должна ломать генерацию ответа или запись истории. User-Agent — заявленная клиентом информация, не подтверждённая идентичность.
6. Старые записи заполнять только при наличии сохранённого User-Agent. Иначе оставлять «Не указан».

## Критерии приёмки

| Входной заголовок | Колонка «Откуда» |
| --- | --- |
| `User-Agent: iris/0.1` | `iris 0.1` |
| `user-agent: iris/0.1 clj-http/3.13.1` | `iris 0.1` |
| `User-Agent: OpenAI/Python 2.8.1` | `OpenAI Python 2.8.1` |
| `User-Agent: custom-client/1.2 (integration)` | `custom-client 1.2` |
| Заголовок отсутствует или пустой | `Не указан` |
| `User-Agent: ???` | `Не распознан` |

Проверить разбор заголовка и полный путь обоих методов API с потоковой передачей ответа и без неё. После обновления страницы название сохраняется; исходный User-Agent доступен в подробностях; ошибки генерации также имеют источник. Неизвестный, длинный или содержащий разметку User-Agent не ломает запрос и интерфейс.

## Основания и ограничения

Формат обозначений описан в [стандарте HTTP](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.1.5). Особые форматы проверены по исходникам официальных клиентских библиотек [OpenAI](https://github.com/openai/openai-python/blob/main/src/openai/_base_client.py), [Anthropic](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/_base_client.py) и [Google](https://github.com/googleapis/python-genai/blob/main/google/genai/_api_client.py).

Это предложение для команды NeuralDeep. Серверный код и реальные входящие заголовки не проверены; конкретное место потери предстоит установить. Изменения клиентского кода Iris в эти требования не входят.
