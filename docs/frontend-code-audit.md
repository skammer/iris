## Замечания

### 1. P1 · Гонки автодополнения

Источник: [public/web-components.js](../public/web-components.js), строки 351, 407–419.

`close()` не инвалидирует запрос; после `response.json()` актуальность ответа
повторно не проверяется. Воспроизведено: очистка поля → запоздалый ответ снова
открывает меню.

Исправить: отменять запрос при закрытии, проверять поколение после всех `await`.

### 2. P1 · Удержание удалённых форм в памяти

Источник: [public/web-components.js](../public/web-components.js), строка 459.

Каждая инициализация добавляет обработчик на `document`, замыкающий форму.
Очистки нет. 11 инициализаций → 11 обработчиков.

Рефакторинг: отдельный компонент автодополнения с
`connectedCallback`/`disconnectedCallback` либо один делегированный обработчик.

### 3. P2 · Повторные запросы при вводе

Источник: [public/web-components.js](../public/web-components.js), строки 428–430.

`input`, `keyup`, `click` независимо вызывают загрузку. Воспроизведено:
`input` + `keyup` → два запроса.

Оптимизировать: debounce, отмена предыдущего запроса, пропуск неизменившегося
префикса. Перемещение курсора обрабатывать отдельно.

### 4. P2 · Глобальная работа на локальные изменения DOM

Источник: [public/web-components.js](../public/web-components.js), строки 472–513, 555–596.

Четыре наблюдателя следят за `document.body`. Изменения чата запускают поиск
форм, проверку маршрута, обработку чисел и математики. KaTeX обходит все
сообщения; debounce 60 мс может откладывать формулы до паузы в непрерывном
стриме. Числовые анимации также содержат принудительный layout через `offsetWidth`.

Оптимизировать: наблюдать нужные контейнеры, собирать изменённые сообщения,
обрабатывать только их. Измерить стоимость layout и глобальных обходов
в браузерном профиле перед дальнейшими оптимизациями.

### 5. P2 · Восстановление соединения теряет черновик

Источник: [public/web-components.js](../public/web-components.js), строки 603–606.

Любое `retries-failed` вызывает перезагрузку страницы. Несохранённый ввод
оказывается под риском.

Исправить: статус соединения и повторное подключение конкретного потока;
сохранять черновик перед вынужденной перезагрузкой.

### 6. P2 · CSS трудно изменять предсказуемо

Источник: [public/app.css](../public/app.css), в частности строки 882, 2180, 4261, 5386.

5444 строки, 137 548 байт до сжатия; поздний блок повторно определяет стили
чата, заданные значительно выше. Каталог компонентов находится в том же файле.

Рефакторинг: разделить исходники по компонентам, объединить разнесённые
определения, явно задать порядок каскада. Каталог отделить от общих компонентов.

### 7. P2 · Браузерная проверка стриминга устарела

Источник: [dev/ui_stream_review.cjs](../dev/ui_stream_review.cjs), строки 10, 52, 55, 58.
Текущее состояние: [src/agent/api/ui_state.clj](../src/agent/api/ui_state.clj).

Скрипт обращается к отсутствующим `ui-session-streams` и `ui-chat-posts`;
состояние уже перенесено в `system[:ui-state]`.

Исправить: обновить fixture, сделать единый запуск браузерных проверок.
Добавить сценарии гонок автодополнения, переключения сессий и восстановления
соединения.

### 8. P3 · Лишние зависимости начальной загрузки

Источник: [src/agent/ui.clj](../src/agent/ui.clj), строки 153–164.

KaTeX загружается на всех страницах; основной JS библиотеки — 276 574 байта
до сжатия. Datastar приходит с внешнего CDN, начальное содержимое требует
дополнительного запроса.

Оптимизировать: локальная закреплённая копия Datastar, отложенный KaTeX,
рассмотреть выдачу начального содержимого сразу в HTML.
